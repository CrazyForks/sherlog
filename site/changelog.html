changelog

Release history for Sherlog. Published artifacts live on GitHub Releases. Sherlog 的版本历史。已发布产物见 GitHub Releases。
v0.5.2 2026-08-17
  • DSH source. shlog can index and search local DSH session history with --source dsh (experimental), same find/read flow as Codex, Claude Code, and Pi.
  • DSH source。shlog 可用 --source dsh 索引并搜索本机 DSH 会话（实验性），find/read 流程与 Codex、Claude Code、Pi 相同。
v0.5.1 2026-08-16
  • Guided upgrades for older indexes. Search commands on an older local index point to one shlog sync that migrates it with a backup; status reports the index format before you act.
  • More tolerant migration. Older local data with historical formatting quirks now upgrades cleanly instead of stopping the whole run.
  • 旧索引升级引导。在旧索引上搜索时，命令会指向一次 shlog sync 完成带备份的迁移；status 会先显示当前索引格式。
  • 迁移更宽容。带历史格式瑕疵的旧数据也能顺利升级，不再中断整个迁移。
v0.5.0 2026-08-16
  • First native release. The production CLI is a standalone Rust binary with bundled SQLite/FTS5; Node.js and TypeScript remain only as development oracles. macOS arm64/x64 and Linux x64 GNU archives ship with SHA-256 checksums, SPDX SBOMs, GitHub attestations, a no-Node installer, and a rendered Homebrew formula.
  • Native index v8. source_files + sessions + documents + documents_fts + coverage + cold_roots become the single SQLite truth; v7 indexes are copied, verified, and atomically migrated by an explicit sync with a retained .v7.bak backup. Old writers fail closed.
  • 首个原生发布。生产 CLI 为内置 SQLite/FTS5 的 standalone Rust binary；Node.js / TypeScript 仅保留为开发 oracle。macOS arm64/x64 与 Linux x64 GNU archive 附带 SHA-256、SPDX SBOM、GitHub attestation、无需 Node 的 installer 与 Homebrew formula。
  • 原生 v8 索引。source_files + sessions + documents + documents_fts + coverage + cold_roots 成为 SQLite 唯一真相；v7 索引由显式 sync copy/verify/atomic 迁移并保留 .v7.bak 备份，旧 writer fail-closed。
v0.4.4 2026-08-14
  • Path-like command ranking. A later title that restates node dist/cli.js publish no longer outranks the session that actually ran the command.
  • Large-message reads keep the query window. read-range --query still centers on the match, and also keeps a short leading slice so cd /path and table headers survive. Dogfood / skill now keep --query next to --seq.
  • Skill: --sort ended is not a date filter; short product names need --cwd or a more distinctive phrase.
  • Path-like 命令排序。后来用标题复述 node dist/cli.js publish 的会话，不再压过真正执行过这条命令的会话。
  • 大消息读取保住 query 窗口。read-range --query 仍以命中为中心，并保留一小段文首，避免 cd /path 和表头被裁掉。Dogfood / skill 会把 --query 和 --seq 一起带上。
  • Skill：--sort ended 不是日期窗；短产品名要加 --cwd，或改用更独特的短语。
v0.4.3 2026-08-14
  • Status no longer loads SQLite. better-sqlite3 is opened only when a command actually needs the body index. --version and sidecar-hit status --selector stay on the metadata sidecar and do not dlopen the native addon. An empty leftover WAL no longer invalidates sidecar identity.
  • status 不再加载 SQLite。better-sqlite3 只在命令真正需要正文库时才打开。--version 和 sidecar 命中的 status --selector 只走元数据 sidecar，不 dlopen native addon。空的残留 WAL 不再让 sidecar identity 失效。
v0.4.2 2026-08-14
  • Status no longer opens the body index. sync writes index.meta.json beside index.sqlite (coverage fingerprints, counts, file-meta cache). status --selector and find coverage proofs read that sidecar when its sqlite+wal identity still matches, and open the body database only as fallback. After upgrade, the next sync creates the sidecar.
  • status 不再打开正文库。sync 在 index.sqlite 旁写入 index.meta.json（coverage 指纹、计数、file-meta cache）。status --selector 和 find 的 coverage 证明在 sidecar 的 sqlite+wal identity 仍匹配时读它，只在缺失或过期时回退打开正文库。升级后下一次 sync 会生成 sidecar。
v0.4.1 2026-08-14
  • Faster coverage proof. status --selector and find prove the requested selector against covering coverage only, instead of replaying every historical cwd/date-range row. Default status --json is a compact proof; pass --inventory for the old audit dump.
  • Smaller index. messages_fts / sessions_fts are contentless FTS5: the inverted index stays, tokenized text is no longer stored twice. The first sync after upgrade rebuilds FTS from already-indexed rows (no transcript re-parse) and may take a while on a large history.
  • 更快的 coverage 证明。status --selector / find 只对能覆盖当前 selector 的 coverage 做 freshness 证明，不再重放每一条历史 cwd/date-range 行。默认 status --json 是紧凑证明；需要旧审计清单时加 --inventory。
  • 更小的 index。messages_fts / sessions_fts 改为 contentless FTS5：倒排索引保留，不再把分词文本再存一份。升级后第一次 sync 会从已索引行重建 FTS（不重新解析 transcript），大库可能要等一会儿。
v0.4.0 2026-08
  • Faster read-only searches on large histories. find and status coverage probes now reuse file metadata cached at sync time and skip re-reading unchanged session files.
  • Recall packet in find --json. Each result carries matchedFields (did the hit come from a real message, or from title / summary / compact / reasoning-summary recall) and sessionMessageCount (the read cost ceiling).
  • Structured zero-result diagnosis. A miss now says whether it is trustworthy (fresh_miss) or unproven (stale_or_missing_coverage), and over-constrained or mixed Chinese/English queries get deterministic broadening suggestions.
  • Eval: duplicate-transcript-family diversity case with top-result diversity metrics in the acceptance gate.
  • Agent skill updated for the recall-packet loop; read-range/read-page help now uses the sessionRef contract.
  • 大历史库上的只读检索更快。find / status 的 coverage 探测复用 sync 时缓存的文件元数据，未变更的 session 文件不再重复读取内容。
  • find --json 新增 recall packet。每条结果带 matchedFields（命中来自真实消息，还是 title / summary / compact / reasoning summary 召回）与 sessionMessageCount（读取成本上限）。
  • 结构化零结果诊断。查不到时明确区分可信 miss（fresh_miss）与 coverage 过期 / 缺失导致的不可信 miss，过长或中英混排 query 会得到确定性放宽建议。
  • Eval：acceptance gate 新增重复 transcript family 多样性 case 与 top 结果多样性指标。
  • Agent skill 同步更新 recall-packet 工作流；read-range/read-page 帮助文案统一为 sessionRef 口径。
